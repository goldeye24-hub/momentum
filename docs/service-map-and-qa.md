# 모멘텀마케팅 3영역 서비스 설계 및 QA 기준 (2026-10-16)

> 기준 저장소: `goldeye24-hub/momentum` (기존 기능 보존). **코드 존재 / 자동 테스트 성공 / 운영 환경에서 실데이터 성공**을 반드시 구분한다.

## 1. 영역 및 권한 경계

| 영역 | 주요 주소 | 이용자 | 제공 목적 | 인증·저장 경계 |
| --- | --- | --- | --- | --- |
| **외부 서비스** | `/`, `/services/*`, `/lab/*`, `/website-samples/*`, `/work/*`, `/industries/*` | 비로그인 방문자 | 상품 소개, 제작 실적, 무료 진단·순위조회, 상담 유입 | 로그인 필수 아님. 무료 실측 기능은 공급자 차단·쿼터의 영향을 받을 수 있고 내부 기록과 구분한다 |

## 2. 기능별 실태 — 코드·테스트에서 확인된 근거

상태 구분:

- **공개 접근 확인**: 외부 GET/비인증 route smoke 검사 통과, API 데이터 기록까지 확인한 것은 아님
- **시뮬레이션 검증**: 모의 DB/API 또는 테스트 계정으로 UI/로직 테스트. 운영 성공과 다름
- **운영 미검증**: 실제 회원 계정·서버 DB 읽기/쓰기 확인 전
- **운영 실패 보고**: 실제 사용자가 오류 화면을 제시함
- **미구현·미활성**: 실사용에 필요한 필수 기능이 아직 없음

| --- | --- | --- |
| 공개 홈페이지, 서비스 페이지, 샘플 보기 | 공개 접근 확인 / 화면 테스트 | GitHub 외부 GET 및 Chromium 공개 UI 검사; 실제 상담 전송은 별도 최종 확인 필요 |

## 3. 버그·개선 우선순위와 완료 조건

### P0 — 서비스 사용 차단
1. **관리자 DB 접근 오류 해결**: `/admin/connection/`에서 9개 테이블 각각의 실패 유형 확인. 해당 Supabase 프로젝트 URL/Secret key 매칭, RLS/권한, 실제 REST 응답을 확인. 기존 테이블·기록을 삭제하지 않는다. *완료*: 관리자 순위 목록 GET 성공 + 등록/조회/삭제 확인 (격리된 QA 데이터).
2. **회원 E2E**: 운영 이메일 인증, 로그인, 내 계정·대상 등록/재로그인 후 조회·삭제 검증. 테스트 계정/개인정보 사용 승인 전 실제 고객 계정에 접근하지 않음.
3. **기본 보안·영역 경계**: 관리자 전용 API는 비로그인·회원 세션에서 401, 회원 API는 비로그인/다른 계정에서 401/404, 공개 라우트는 공개 접근 유지. 비밀키 프런트 노출 금지.

### P1 — 사용 가치 검증
4. 수동 실제 순위 관측 → 저장된 snapshot → 관리·회원 화면 일치 확인. 실패·미관측 수치를 가짜 순위로 채우지 않는다.
5. 경쟁업체·키워드 리포트의 실제 데이터 포함 여부, 관측 날짜·기준 일치 확인.
6. 회원 정보와 관리자 분석 데이터를 한 소스 기준으로 설계하고 소유권·보안 정책 검토.

### P2 — 지속 운영 준비
7. 정기 수집 큐·제한·재시도 정책, 크론 및 네이버 이용규칙 점검 후 활성화.
8. CRM/디자인 데이터 서버 저장·마이그레이션 계획 수립. 기존 브라우저 데이터를 삭제하거나 자동 덮어쓰지 않는다.
9. 오류 추적·알림·감사 로그, 접근권한과 정기 회귀 검사.
10. 유료 결제·구독·서브관리자 등은 비용·정책·개인정보 보호 검증 후 별도 승인.

## 4. 변경 시 필수 QA

- **유형 1: 코드**. 라우트, UI/입력/인증, 데이터 연산, 권한·보안, 런타임 오류 테스트.
- **유형 2: 실제 외부 공개**. 운영 URL의 HTTP 상태·메타·자산·브라우저 실행을 별도로 검사.
- **유형 3: 운영 인증·실데이터**. 정당한 테스트 계정으로 회원/관리자 흐름을 실제 DB에 대해 확인. 접근권한이 없으면 *미검증*.
- **유형 4: 배포**. Vercel Production 배포와 최종 커밋 일치 확인. Hobby 일일 배포 한도 초과 시 배포 전 상태로 표시.
- **상태 전환**: `코드 작성` → `테스트 통과` → `배포 성공` → `운영 검증`. 마지막 단계까지 통과하기 전에는 완료라고 표현하지 않는다.
- **배포 보류 상황**: 새 브랜치/PR 코드는 운영에 반영됐다고 보고하지 않는다.

### 보존해야 할 것
기존 GitHub/Vercel 프로젝트, 새 `momentum-marketing` DB 9개 테이블, 무료 공개 도구, 관리자 CRM 로컬 백업, 각 서비스 URL, 관리자가 입력한 기록. 다른 Supabase 프로젝트 `support-match-loop`는 수정하지 않는다.
