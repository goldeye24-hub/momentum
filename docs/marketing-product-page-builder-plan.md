# 모멘텀마케팅 — 마케팅 상품 상세페이지 자동제작 시스템 설계서
작성일: 2026-10-23 · 상태: **설계만 완료** (관리자 상품 편집/자동 발행 기능 미구현)
관련 작업 브랜치: `feature/marketing-platform-20261023` · PR #64 미병합

## 1. 목표와 범위
모멘텀마케팅 메인은 종합 온라인 광고대행사 홈페이지를 유지한다. 상품 등록 담당자는 복잡한 글·코딩·SEO를 몰라도 **실제 제공 조건을 입력**하면 정형화된 마케팅 상세페이지의 문구·도표·FAQ·SEO 메타·모바일 화면이 만들어지도록 한다. 최종 발행은 관리자 검수/명시적 승인 이후에만 진행한다. 디자인/제작 브랜드는 별도 모멘텀에이전시로 연결한다.

기존 `/admin/studio/`는 **고객용 업종 홈페이지 디자인 편집** 도구이고, 브라우저 임시저장+HTML 내보내기 모델이다. 상품 상세페이지 CMS와 혼동하지 않으며 기존 기능을 건드리지 않는다.
기존 `/admin/overview/` 운영센터, `api/admin-site-builder.js` 관리자 인증 기능을 가능한 범위에서 재사용한다. 운영 DB 연결·서버 영속저장이 검증됐다고 가정하지 않는다.

2차 확장: 오픈패키지 1/2 상세페이지와 유료 회원서비스 안내. 첫 MVP는 위 8개만.
상단 메뉴 URL은 해당 페이지가 실배포되고 QA 완료된 시점에 `#section` 앵커에서 새 경로로 전환한다. 미발행 URL을 미리 노출하지 않는다.

## 3. 관리자 입력 최소화 설계
첫 페이지 생성 시 8개 상품에 공통 설명과 초안 FAQ/서비스별 절차를 선작성한다. 관리자는 아래 **4가지 항목만 확인·수정**하면 최초 미리보기를 생성할 수 있다.

**필수 확인 4개**
1. 실제 제공 업무: 체크리스트(해당 상품 템플릿에 미리 채워진 기본값)에서 선택·수정.
2. 제공하지 않는 업무/별도 비용: 외부 매체 광고비, 촬영 출장비, 기자단 비용 등 실제 조건 선택; **빈칸이면 관련 문구 게시 금지**.
3. 견적 정책: `상담 후 견적`(초깃값) 또는 근거 있는 금액·단위·부가세 적용 여부.
4. 진행 조건: 착수 준비물·지역·업체 계정 권한·기간 등 확인된 내용; 미확정 항목은 숨김.

**선택**
- 차별점 1~3개(근거 없는 성과 수치 금지), 작업 이미지(권한 확인), 납품물, 고객 FAQ 수정, 실제 사례/리뷰(허가 및 증빙 필요), 내부 담당자 메모(비공개).
- **추정/AI 생성으로 채우지 말 것**: 가격, 기간, 보장 실적, 고객 이름·로고, 후기, 계약 조건, 매체 게재 확정, 검색순위/매출 수치.

## 4. 생성 결과의 공통 섹션
A. 서비스별 차별화된 헤드라인/간단 정의 + 대표 CTA
B. 해당 상품이 필요한 고객 상황 3~4개
C. 업무 범위(포함/제외) 4~8항목
D. 도식·매체 비교·진행 과정 3~5단계(상품에 맞는 시각 요소)
E. 고객 준비물 / 제공 산출물 / 예상 진행 절차
F. 견적 방식과 외부 비용(확인된 내용만 표시)
G. 서비스별 FAQ 3~6개(사실확인된 답변)
H. 관련 무료도구/다른 서비스 내부링크, 상담 CTA
I. SEO 메타 제목·설명, canonical, OG, breadcrumb, 적합한 구조화 데이터

**페이지 차별화 요소**
- 검색광고: 포털별 비교표·키워드/예산 분류도 (임의 성과 수치 금지)
- 플레이스: 점검 항목 체크리스트·예약 흐름도
- 리뷰관리: 신고 가능 요건/공식 절차/불가 사례(삭제 보장 절대 금지)
- 바이럴: 블로그 콘텐츠형 vs 체험단 비교, 광고·협찬 표시
- SNS: 인스타·인플루언서·샤오홍슈 채널별 대상·협업 과정
- 언론홍보: 원고→검수→매체심사→게재 프로세스, 기사 게재 미보장
- 촬영: 컷 유형·콘티·촬영 준비 안내, 허가된 이미지에 한해 게재
- 광고교육: 교육 모듈·수준별 커리큘럼, 사후 직접 운영 범위

## 5. 입력 → 발행 플로우 (첫 단계는 안전한 반자동)
1. 기존 관리자 인증으로 `/admin/services/` 접속. 상품 선택.
2. 기본 문구/체크 항목 표시, 관리자는 네 가지 사항 확인·입력.
3. `초안 저장`은 **서버에 저장되게 구현**: 처음 단계는 GitHub에 버전관리되는 JSON 초안 또는 승인된 DB 활용. 기존 홈페이지 제작 스튜디오의 localStorage를 실운영 저장으로 재사용하지 않음.
4. `미리보기 생성` 시 HTML 자동 작성(정적 페이지 빌드) 및 모바일 확인. 필요한 메타/스키마도 함께 생성.
5. `발행 요청` 후 관리자 승인. 승인된 콘텐츠만 GitHub 변경/PR로 반영, Vercel 프리뷰 검증, `main` 머지로 공개.
6. 되돌리기: 이전 JSON/커밋을 복원한 뒤 재배포. 발행 상태(초안/검토/게시/중단) 관리.
7. 발행 성공 후 홈페이지 메뉴 연결, 사이트맵 포함, 검색엔진 수집 확인. 수집·순위를 보장하지 않음.

**저비용 우선**: Vercel 새 함수 추가 없이 현행 관리자 핸들러 라우팅을 확장하는 방식을 검토(현재 Hobby 예산/라우팅 제약 확인 필수). 공개 상세페이지는 정적 HTML로 생성해 별도 DB 조회/AI API 호출 없이 제공. GitHub 쓰기 자격 증명은 **서버 전용 최소 권한**, 관리자 CSRF·인증·상품 값 검증·배포 승인 필수. 사용자 브라우저에 토큰 노출 금지. 입력할 때마다 AI API 호출하지 않고 템플릿 기반 + 필요시에만 문구 제안.

## 6. 상품 데이터 최소 스키마
```json
{
  "slug": "keyword-ads",
  "title": "키워드광고",
  "subtitle": "네이버·구글·카카오",
  "status": "draft",
  "service_scope": ["키워드 조사", "광고 캠페인 설정", "운영 점검"],
  "exclusions": ["매체 광고비 별도"],
  "pricing": {"mode": "consultation", "amount": null, "unit": null},
  "conditions": [],
  "proof": [],
  "images": [],
  "faq_overrides": [],
  "related_tools": [],
  "last_reviewed_at": null,
  "approved": false
}
```
이 스키마는 구현 설계 예시이고 아직 저장·게시 기능은 없다. 특정 서비스의 기본 범위는 관리자 검증 전 **초안 예시**로 표시한다.

## 7. 검수 기준
- 상품 8개에 정확히 대응하는 URL/제목/CTA. 디자인은 모멘텀에이전시로, 무료도구는 기존 경로로.
- PC 1440px / 모바일 390px 및 768px에서 가로 넘침·이미지 깨짐·탭 불가 없음.
- 각 CTA가 해당 상품을 지정한 상담 화면으로 연결(기존 data-product/options 값 활용).
- 누락 가격/기간/실적을 만들어내지 않음; 수정·등록 대행과 플레이스 SEO 점검 구분.
- 모든 메타/OG/canonical/사이트맵/모바일 레이아웃 작동.
- 외부 API 미연결 상태여도 공개 페이지 정상; 새 페이지 때문에 운영 비용 급증하지 않음.
- 기존 운영 홈페이지·회원·관리자 경로와 사진 미사용 결정 유지.
- 전체 GitHub Actions 중 디자인 포트폴리오의 **기존 실패**는 별도 추적하고, 상품 상세페이지 QA는 독립적으로 확인.

## 8. 구현 순서
**Phase A: 기반 설계** — 상품 데이터 스키마·8개 선작성 초안·공통 디자인 컴포넌트·고유 섹션/FAQ 초안
**Phase B: 관리자 입력** — `/admin/services/` 상품 목록·실제 제공 범위 체크·초안 저장·PC/모바일 미리보기
**Phase C: 자동화** — 정적 상세페이지 생성, SEO/OG/사이트맵, 프리뷰 배포, 승인/복원
**Phase D: 검수/공개** — 실서비스 조건 확인, 링크·폼·접근성·성능 검사, 단계적 배포

**운영 원칙: 사용자는 서비스 제공 범위·조건의 사실 여부와 발행 승인만 책임지고, 나머지 기본 문구·구성·디자인·자동 생성/배포 파이프라인은 시스템이 담당하도록 설계한다.**
