# 애드로그 기능 벤치마킹 전수 목록 및 모멘텀 개발 매핑 (2026-10-16)

> **근거의 경계:** 과거 사용자 제공 캡처를 이전 대화에서 정리한 기능명(회수된 과거 기록) + 애드로그 공식 공개 홈페이지 기능 목록 + 공개 API 문서 + `momentum` GitHub 현재 코드. **이 문서는 과거 캡처 이미지 원본을 직접 재열람한 결과가 아니다.** 일부 로그인 전용 화면과 2026년 신규 공지의 모든 내부 기능은 독립 재검증하지 못했다.

### 확인하지 않은 사항
- 로그인 전용 세부 메뉴별 검색 항목, 정확한 업데이트 빈도, 상품별 요금, 공개 UI의 작동 여부.
- 과거 이미지 원본의 픽셀 단위 레이아웃. 현재 접근 가능한 것은 대화에서 요약된 기능명이며 원본 캡처를 다시 봤다고 주장하지 않는다.
- 애드로그에서 '쇼핑몰 SEO/GEO 종합 개선 처방'과 동일한 기능을 공식 제공한다는 증거. **이는 모멘텀의 독자 기능 기획**이다.

## 2. 애드로그의 다중 키워드·그룹 데이터 설계 벤치마킹
- 공식 플레이스 키워드 조회 API에 `group_no`, `group_name`, `keyword`, `keyword2`, `place_id`, `place_name`, `month_count`, `detail_keyword`, `search_date`, `memo` 등이 명시되어 있다. 하나의 업체에 대해 여러 키워드를 그룹화해 추적하는 모델을 채택한다.
- 모멘텀 DB의 `momentum_member_targets`는 현재 업체×키워드 개별 행은 가능하지만 **업체-지점/키워드그룹 관계·일괄등록·종합진단·대규모 예약 측정은 미구현 또는 미검증**.
- 원하는 UI: **회원→등록 매장/스토어→(상품/지점)→키워드 그룹→복수 키워드→관측 이력**.
- 한 화면의 표: 키워드명, 검색표면, 현재 순위, 전일/7/30일 변화, 월검색량, 경쟁 업체 상위3, 측정 일시, 신뢰도 및 상태. 키워드 전체 일괄 추가/중지/삭제/그룹변경·CSV.
- 등록 30건과 측정 30건은 다르다. 상업 이용권/쿼터에 맞춰 측정 큐, 스케줄, 자원 비용, 제한/실패 상태를 분명히 보여준다.

## 3. 모멘텀 차별화 기능(애드로그 공식 기능이라고 주장하지 않음)
- **플레이스 중심 SEO**: 업체 기본 정보, 메뉴·가격, 사진, 리뷰, 지역/속성, 예약·전화·길찾기, 키워드-업체 적합성 근거를 세부 점검.
- **플레이스 중심 GEO**: 사용자 질문 유형별 AI 응답에서 업체의 언급·설명·출처 인용을 기록; 업체 정보의 플랫폼 간 일관성 진단. 기계가 만든 공식 점수가 아니다.
- **경쟁 원인 분석**: 같은 관측 조건에서 복수 업체 비교 → 부족한 콘텐츠/정보·대응안.
- **실행 처방**: 증거·추정 구분 → 중요도 → 개선 문구/사진/콘텐츠/리뷰 답변 가이드 → 체크리스트 → 재측정. 허위 리뷰·순위조작 금지.
- **쇼핑 진단**: 네이버/쿠팡/오늘의집 등 가능한 검색 순위 외에 상품명/카테고리/속성/가격/배송/상세페이지·사진/공개 리뷰 차이와 개선 과제; 매출/전환수는 소유자 승인 연동시에만 제공.
- **광고 추천**: 실제 유입/전환·키워드 경쟁력 확인 후 광고 테스트 여부와 비용·한계를 함께 안내. 근거 없는 광고비 집행 권유 금지.

## 5. 개발 우선순위와 출시 게이트
1. **P0 장애**: 프로덕션 코드 일치, 관리자 Supabase DB 오류, 회원 인증/실저장, 데이터 정확성·보안.
2. **핵심 유료가치 P1**: 매장별 다중 키워드 등록/그룹/이력, 실제 플레이스 순위표, 상위 경쟁사 비교, 플레이스 SEO/GEO 근거별 자체 진단·AI 개선 처방.
3. **공개 전환 P1**: 홈페이지 상품/설득·포트폴리오/마케팅 정보, 무료 키워드 검색량·플레이스 일 2회·상권·시즌 추이. 공개 자료 권한 확인.
4. **확장 P2/P3**: 블로그/통합웹/클립/인플루언서, 스마트스토어·N가격비교, 쿠팡/오늘의집, 자동 알림·리포트, 정식 결제/구독.
5. **완료 기준**: 코드 → 자동 테스트 → Vercel Production 배포 → 실제 소유자 계정/DB와 정상 사용자 동작 → 오류/데이터 검증. 앞선 단계는 완료로 보고하지 않음.

변경 필요 시 `docs/product-architecture-v2.md`와 `docs/service-map-and-qa.md`를 함께 점검한다. 기존 CRM·디자인 편집과 DB 데이터 절대 초기화 금지.
