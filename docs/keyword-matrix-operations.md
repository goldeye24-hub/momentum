# 모멘텀 모바일 키워드 순위 매트릭스 — 관리자 파일럿

## 기능
- 관리자 전용 `/admin/keyword-matrix/`에서 `포항맛집`과 같은 키워드를 조회합니다.
- `기존 기록 조회`는 저장된 Supabase 관측 이력만 읽습니다. 네이버에 새 요청을 하지 않습니다.
- `새 모바일 목록 관측`은 기존 `runMobileList`와 공통 요청 게이트를 통해 실측 결과만 수집합니다. 가짜 순위나 임의 가상의 업체는 기록하지 않습니다.
- 최근 7일·30일·90일에 저장된 **서울 시간 기준 날짜별 최신 실제 관측**을 사용합니다.
- TOP 10/30/100 매트릭스, ID별 직전 관측 비교, 상승/하락, 누적 그래프, CSV가 지원됩니다.
- 이전 날짜에만 등장한 업체도 날짜별 원본 컬럼에 남습니다. 미관측 셀은 빈칸입니다.

## 관리자 초기 활성화
1. Supabase SQL Editor에서 `db/rank-live-cache.sql`을 먼저 적용합니다.
2. 이어서 `db/rank-keyword-history.sql`을 적용합니다. 이 SQL은 공통 소스 게이트와 별도로 키워드별 스냅샷·항목 및 저장/날짜별 조회 DB 함수를 생성합니다.
3. Vercel `momentum` 프로젝트의 **서버 환경변수**에 `MOMENTUM_RANK_DB_URL`, `MOMENTUM_RANK_DB_SERVICE_KEY`를 연결합니다. 서비스 역할 키를 GitHub 코드·브라우저·채팅 메시지에 게시하면 안 됩니다.
4. 관리자 세션이 없다면 기존 `MOMENTUM_ADMIN_PASSWORD`(16자 이상), `MOMENTUM_SESSION_SECRET`(32자 이상) 설정이 필요합니다.
5. 승인된 Preview/Production 배포에서 `/admin/keyword-matrix/`로 접속한 뒤 먼저 `기존 기록 조회`를 실행합니다.
6. 실제 관측은 관리자만 실행할 수 있으며, 네이버에서 429/403이 나오면 즉시 중단해야 합니다.

## 증거 및 정확도
- 조회 결과는 네이버 **모바일 플레이스 목록에 관측된 표시 위치**입니다. 광고 제외 자연검색 확정 순위가 아닙니다.
- 제공자의 순위 메타가 있으면 목록 표기 순위를 사용하고, 메타가 없거나 순서가 재시작되면 근사치로 표시합니다.
- 업체는 숫자 Place ID로 구분하므로 동명이 업체를 합치지 않습니다.
- 날짜별 차이는 양쪽 관측 모두 동일한 Place ID가 포함되었을 때만 계산합니다. 다른 날짜에 보이지 않았다는 이유로 신규 진입 또는 탈락으로 단정하지 않습니다.
- 인증 없는 외부 고객에게 원본 관측 목록을 제공하지 않습니다.

## 확장 로드맵
- 1차: 현재 내부 관리자용 모바일 키워드 스냅샷과 비교표 검증.
- 2차: 합법적인 자료 공급 방식 및 정확도 확인 후 정기 측정 큐/일간 알림.
- 3차: Supabase Auth 또는 동등한 고객 인증과 업체별 접근 정책·대행사 그룹.
- 4차: 검증된 슬롯제·결제·사용량 및 경쟁사 추천, 히든 키워드 발굴 엔진.
- 5차: 블로그·쇼핑·클립용 별도 데이터 소스와 권한·정확도 검증.

Vercel의 현재 빌드 제한과 프로젝트 연결 권한이 해결되기 전에는 **운영 배포 성공을 주장하면 안 됩니다**. 수백 명의 실제 사용자를 위한 상업 운영 준비도 아직 끝나지 않았습니다.
