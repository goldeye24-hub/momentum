# 모멘텀 모바일 순위조회 — 파일럿 운영 안내

## 실제 순위의 의미
- 모바일 네이버 플레이스 목록에서 실제 관측된 표시 위치입니다. 광고 제외 자연검색 순위나 개인화와 무관한 절대 순위가 아닙니다.
- 업체명은 동명 업체 문제 때문에 근사치로 처리할 수 있으므로 네이버 플레이스 숫자 ID를 권장합니다.
- 측정에 실패한 값은 없는 순위로 만들어 저장하지 않습니다.

## 429 보호
- 성공 결과는 30분 동안 재사용하며 원래의 관측 시각을 보존합니다. 동일 값을 다시 읽어도 누적 그래프에 새 관측값으로 등록하지 않습니다.
- 같은 서버에서 동시에 들어온 동일 입력은 하나의 브라우저 측정만 실행합니다.
- IP 기준 신규 조회는 10분에 3회까지 허용하고, 캐시 재조회는 차감하지 않습니다.
- 네이버가 HTTP 429/403을 반환하면 다른 주소로 재시도하지 않고 즉시 중단합니다.
- 서버 프로세스 단위 보호만으로는 여러 Vercel 인스턴스 사이에 제한이 공유되지 않으므로 유료 서비스에는 공유 저장소가 필수입니다.

## Supabase 공유 캐시·요청 게이트 설정
1. 비공개 Supabase 프로젝트 SQL Editor에서 db/rank-live-cache.sql 실행. 기존 자동 순위 기록도 사용할 경우 db/rank-watch.sql 실행.
2. Vercel 서버 환경변수 MOMENTUM_RANK_DB_URL 에 Supabase 프로젝트 HTTPS URL 설정.
3. MOMENTUM_RANK_DB_SERVICE_KEY 에 Supabase 서비스 역할 키 설정. 이 키를 브라우저/코드 저장소/지원 대화에 공유하지 마세요.
4. 이후 같은 키워드·업체의 30분 기록을 서버 간 재사용합니다. 새 외부 측정은 SQL 트랜잭션으로 출처별 최소 60초 간격으로 직렬화하고, 429/403은 최소 1시간 쿨다운으로 저장합니다.
5. 공유 저장소가 설정됐지만 접근 오류가 발생하면 안전을 위해 새 자동 측정을 중단합니다.

## 배포 및 상업화 조건
- 아직 운영 Vercel 배포 성공을 검증하지 못했습니다. Vercel 프로젝트에 앱 접근권한과 빌드 여유가 필요합니다.
- 네이버 자동화 접근 및 데이터 활용·고객 판매 가능 범위에 대한 권리/허락 여부를 확인해야 합니다. 429 제어는 접근 허가를 대신하지 않습니다.
- 네이버 공식 지역 검색 API는 모바일 플레이스 전체 노출 순위 API가 아닙니다.
- Vercel Hobby는 비상업적 개인 용도입니다. 유료 서비스라면 상업 이용이 허용되는 호스팅을 선택합니다.
- 매일 자동 측정은 아직 실제 스케줄이 설정되지 않았습니다. MOMENTUM_RANK_CRON_ENABLED를 임의로 켜지 마세요. 공급자 권한과 용량을 확보하고 Cron을 연결해야 합니다.

## 확인 항목
- GitHub Actions에서 Node 및 브라우저 자동 테스트가 통과하는지 확인합니다.
- 웹화면은 /lab/rank/, 관리자 화면은 /admin/watches/ 입니다.
- 성공한 결과를 다시 읽을 때 cached=true 와 원래 관측 시각이 유지되어야 합니다.
- 네이버 429/403 처리시 신규 외부 요청을 멈추고 과거 결과는 stale로 명확하게 표시해야 합니다.
- 실제 네이버에 의도적으로 반복적인 부하를 주는 시험 대신 단위 테스트의 가짜 오류 응답으로 검증합니다.
