## A. 공개 홈페이지 — 신규 고객 유치
- 소개·설득: 모멘텀의 접근법, 문제 해결 방식, 서비스 차별화, 과정, 성과 증빙.
- 마케팅 상품: 플레이스·로컬 SEO/검색광고, 블로그·바이럴, SNS, 홈페이지, 상세페이지, 통합 광고대행. 마케팅 가격·혜택 과장 금지.
- **마케팅 최신 트렌드 및 정보**: 플랫폼 변경·현장 전략·업종별 사례. 날짜·출처·업데이트 시각 표기. 관리자에서 글 검수·발행.
- **포트폴리오 독립 3분류**: 홈페이지, 상세페이지, 브랜드블로그(홈 디자인/브랜딩/운영). 실제 납품 vs 데모 구분; 고객 허락과 저작권 준수.
- 광고 문의: 업종·상호·연락처·기대목표·선택 상품; 상담/견적 CRM으로 연결.
- 무료서비스 독립 4개:
  1. 키워드 검색량 조회(측정치 및 출처/측정일 표시)
  2. 플레이스 순위 확인 **비회원 하루 2회**(실측 성공만 순위로 표시; 기준 위치·기기·키워드·관측시각·범위를 명시; 오남용·봇 차단 및 분산 쿼터 설계)
  3. 상권정보(공식/공공 데이터 기반 점포·업종·변화, 유동인구·매출·실시간 현황은 확보 전 미제공)
  4. 시즌별 검색어 추이(상대지수와 실제 검색량 구분)
- 홈페이지 메인: 전문 광고대행사 브랜드 중심; 분석도구/회원 영역은 분명한 CTA. 모바일 우선.

## B. 회원 플랫폼 — 핵심 상품
**기본 질문: 내 매장이 어디에서 얼마나 노출되는가? 경쟁업체보다 부족한 점은? 무엇을 수정할까? 수정 후 실제 개선되었나?**

### 필수 입력 및 근거
- 상호, 업종, 지점, 지역/상권, 네이버 플레이스 숫자 ID 또는 URL; 선택: 홈페이지, 블로그, SNS, **복수 검색 키워드와 그룹**, 문의/예약 목표. 쇼핑몰/스마트스토어는 별도 상점·상품 URL/식별자 모델을 사용한다.
- 선택적 연결/승인: GA4, Search Console, 네이버 관련 계정/분석, 광고계정 등. 미연결 데이터는 보유하지 않는다고 정확하게 표시.
- 결과마다 측정 시점, 기기·지역·검색 표면, 측정 방식, 출처, 신뢰도, 측정 실패 상태. **측정하지 않은 순위/조회수/경쟁사 매출을 임의 생성하지 않음**.
- 대상 상권·업종·검색 의도별 비교집단을 구분. 경쟁사 자료는 합법적으로 확보한 공개 데이터·승인 데이터만 사용.

### 대시보드와 진단 엔진
1. **내 매장 종합 성적표:** 포털 플레이스/웹검색 실제 관측 순위, 가용한 검색 노출/클릭/문의 지표, 자사 진단 종합·영역 점수. 공식 알고리즘 점수로 속이지 않음.
2. **플레이스 SEO(검색 최적화) 진단:** 핵심 대상은 **네이버 플레이스 업체 정보 및 플레이스 검색 노출**이다. 업체 카테고리·상호·주소·영업시간·메뉴/가격·서비스·사진·편의시설·지역·대표키워드, 검색 의도와 정보 일치, 예약/전화/길찾기 동선을 점검한다. 키워드별 실제 관측 순위와 확인 가능한 콘텐츠 완성도를 구분한다. 홈페이지의 title/description·색인·구조화 데이터 같은 **웹사이트 SEO는 보조 연동 진단**이지 이 메뉴의 주 대상이 아니다.
3. **플레이스 중심 GEO(AI 검색 대응) 진단:** 사용자가 '이 지역에서 조건에 맞는 매장'을 묻는 AI 검색 상황에 대해 **해당 업체가 어떻게 식별·설명·추천·출처 인용되는지**를 표본 질문으로 점검한다. 플레이스·공식 사이트·지도·공개 정보의 상호·주소·분류·메뉴·영업시간 일관성과 실제 고객이 궁금해하는 정보의 충분성을 평가하고 보완 사항을 제시한다. AI 응답은 시간·모델·질문에 따라 달라지므로 **측정한 답변/출처만 제시**하고 'AI 노출 점수'는 자체 진단 항목으로만 구분한다. 네이버 플레이스 공식 점수나 순위 상승 보장이 아니다.
4. **플레이스 개선:** 업체 정보·분류·영업시간·메뉴/가격·사진·예약/문의 동선·대표 키워드와 검색 의도 정합성·리뷰 응대.
5. **경쟁업체 비교:** 같은 지역/업종/키워드의 실제 관측 순위 및 확인 가능한 정보 완성도, 리뷰 수·속성·콘텐츠, 검색 노출 격차. 순위를 좌우하는 공식 가중치를 안다고 주장하지 않음.
6. **개선처방/실행 체크리스트:** `문제 근거→영향 가능성→추천 변경→실행 방법→난이도·비용·우선순위→완료 여부→재측정` 흐름. 수행 도구/콘텐츠 초안·담당자·상담전환.
   - 블로그: 부족한 검색 의도/정보와 보유 콘텐츠를 비교하여 업데이트/새 콘텐츠 주제와 이유 제안. 단순 업로드 횟수 증가를 기계적으로 처방하지 않음.
   - 영수증/방문자 리뷰: **실제 이용자의 자발적·진정한 경험** 유도와 응대 가이드. 허위·대리 리뷰, 보상 조건을 숨긴 후기, 획일적 키워드 삽입 지시 금지.
   - 트래픽·광고: 측정 가능한 유입/전환/광고 경쟁 상황을 확인했을 때 비용 대비 가능성을 설명하며 예산 제안. 연결되지 않은 통계는 미확인으로 표시.
7. **성과 추적:** 7/30/90일 순위 기록, 작업 전후 비교, 조회/클릭/전화/예약 등 연결 가능한 지표, 리포트와 알림.

### 자체 개발 애드로그형 기능 — 참고기능 전체 관리 원칙
- 핵심: 플레이스 ID/기본정보/히든키워드 후보·**다중 키워드별** 순위·변동·리뷰·저장 지표, 1회 조회, 키워드/경쟁사 추세, 블로그 게시물 순위, 통합웹 순위, 인플루언서 순위, 키워드 조합/확장.
- **쇼핑몰/스마트스토어 별도 모듈**: 애드로그 공개 목록에 **네이버 가격비교 상품 순위 및 N+ 스토어 순위 체크**가 확인됨(2026-10-16). 이에 준하는 **상품별·복수 키워드별 쇼핑 검색순위 추적**은 개발 대상이다. 추가로 **상품 상세정보·상품명/검색어 적합성·가격/배송·이미지/설명·리뷰·상세페이지 전환 요소·경쟁상품 차이** 등 '쇼핑몰 진단 및 개선 처방'을 자체 차별화 기능으로 설계한다. 후자는 애드로그에서 동일 진단 상품을 제공한다고 확정하지 않는다. 판매·전환수는 적법한 연동 데이터가 없으면 '미확인' 처리.
- 확장 대상 목록: 펜션 예약 관련 순위 및 기타 공식 사이트에 명시된 도구. 로컬 플레이스 핵심 UX와 쇼핑 분석 UX를 **업종/매장 유형에 따라 분리**하며 수요·데이터 권한·운영비 검증 뒤 단계적 공개.
- **지식인 관련 서비스는 종전 제외 지시 보존**. 기능 전체 재현과 충돌할 경우 별도 승인 전까지 공개·판매·우선개발에 포함하지 않음.
- 경쟁 서비스의 내부 소스/상표/비공개 API를 복제한다는 뜻이 아님. 제공 가치와 기능 범위를 자체 구현하되 자료 수집 및 상업 이용권 검증이 필요.
- 회원 소유권 기반 목표/슬롯/기록 분리, 결제·구독·권한, 자동 스케줄, 분산 요청 한도, 실패/429 방어 및 비용 상한 설계.
  
### 다중 키워드 동시 관리 — 필수 요구사항
- **매장당 키워드 1개 제한이 아님**: 한 매장에 수십 개 이상의 키워드를 등록·그룹화하고(예: 부산돼지갈비 / 부산고기집 / 수영구맛집 / 광안리회식 / 수영구돼지갈비), 한 화면에서 **전체 키워드 순위·전일/7일/30일 변화·검색량·경쟁업체·측정일**을 표로 비교한다. 여러 매장도 같은 계정에서 관리한다.
- **일괄 등록·관리**: 줄바꿈·쉼표 입력, CSV 업로드, 키워드 조합기·추천 후보에서 다중 선택 → 중복 제거 → 일괄 등록/삭제/중지/재개; 검색·필터·정렬, 중요 키워드 표시, 지점별/업종별 그룹을 지원한다.
- **전체 키워드 묶음의 공통 진단**: 매장별 대표 키워드군의 노출 분포, 강세/약세, 경쟁업체 대비 격차, 새로 추가할 키워드와 제외할 키워드를 제안한다. 단일 키워드의 순위가 매장 전체 평가를 결정하지 않도록 한다.
- **다중 키워드 이력 및 측정**: 각 `매장 ID + 검색표면(모바일 플레이스/PC 지도/통합웹/블로그/쇼핑 등) + 키워드 + 관측조건` 별로 스냅샷을 보유하며, 기기·지역·일자·출처가 다르면 혼합하지 않는다. DB 기록 없이 화면에서 가짜 추세 생성 금지. 사용량은 유료 플랜별 **활성 추적 키워드×대상×검색표면 수**에 따라 공정하게 정의·표시하고, 한도 초과 시 저장 자료를 보존하되 신규 등록/측정만 제한한다.
- **대량 순위 측정은 무제한 동시 외부 호출을 의미하지 않음**: 공급자별 상업적 이용권·요청량·큐/분산 제한·429 쿨다운을 지키며 순차/분산 스케줄로 측정한다. 실패 건은 미관측으로 남긴다.
- **현행 코드와의 차이**: `momentum_member_targets`는 업체×키워드별 **복수 행을 저장할 수 있는 구조**이나, 회원 기본 `slot_limit=1`, `member-watches`의 **한 건씩 등록 UI**, 실제 일괄 추가/그룹/동시 자동 추적은 미구현 또는 운영 미검증이다. 무료 파일럿 1슬롯을 서비스 최종 요구사항으로 간주하지 않는다.
- **쇼핑몰 다중 키워드**: 1개 상점 아래 여러 상품, 상품별 복수 키워드/가격비교·N+ 스토어 검색표면을 분리 관리. 상품별 진단과 개선 전후 이력을 연결한다.
  

### 점수와 설명의 신뢰성
- 점수는 **모멘텀 자체 체크리스트/휴리스틱**. 공식 네이버·구글·AI 랭킹 점수와 구분하고 항목별 근거/측정일/산식·범위를 노출.
- 미측정 지표는 null/미확인, 가짜 0점 금지. 경쟁 비교 표본과 기준을 명시.
- 결과는 확률적 가설·개선 후보이지 '이 조치를 하면 N위 상승'을 보장하지 않음.

## C. 관리자 통합 운영센터
- 회원·이용권·결제·영수증/환불·권한/접근 로그 및 회원별 데이터 격리.
- 도구·API 통제: 무료조회 일일 2회(공유 서버/DB 기준), 대상/키워드 슬롯, 자동 수집/정기 작업, 429/403 제한, 실측 실패 큐·수집 비용·오류 로그, 외부 데이터 계약.
- 고객·영업 CRM: 유입 문의→상담→견적→계약→작업→청구→재계약.
- 사이트·광고: 마케팅 상품, 포트폴리오, 트렌드 글, SEO, 배너/팝업/광고영역, 상담 유도 및 광고 소재.
- 통계·오류: 방문→무료 도구 사용→회원가입→유료 전환→상담/계약 퍼널, 가입/활성/이탈, 배포·DB·API 오류, 감사로그. 데이터 자체 미수집일 때 추정 숫자 표시 금지.
- 마케팅 실행/게시/발송/광고비 등 고객 영향을 주는 조치는 관리자 확인 후 수행.
