# 모멘텀마케팅 네이버 플레이스 순위조회 재개발 점검
기준일: 2026-10-28

## 확인된 장애와 진단 근거
- 공개 순위조회: https://momentum-orcin-delta.vercel.app/lab/rank/
- 기존 서버 경로: `/api/place-rank-live`. Playwright + @sparticuz/chromium으로 모바일 플레이스 목록, PC 지도 목록, PC 통합검색 플레이스 블록을 별도 관측한다.
- 장애 지점: 공유 저장소의 첫 `rank_live_snapshots` 조회(`read-cache`)가 실패, 원인 코드 `ENOTFOUND`. Supabase URL은 형식상 정상이어도 런타임에서 DNS를 찾지 못했다. **저장소 테이블 누락이나 비밀번호 오류로 단정하지 않음**.
- 2026-10-28 운영 API 재검사: 검색어 `부산 미용실`, 테스트 ID `2085358113`, 범위 모바일. 실제 모바일 업체 **107개 관측**, 대상은 조회 범위에 없어서 `status=not_in_block`, `rank=null`. 해당 ID의 정상적인 업종·순위를 보장하는 테스트는 아님. 즉 목록 접근 및 판독 경로는 실제 작동하나 **특정 매장의 순위 정확도는 별도 테스트 필요**.

## 신규 동작
1. 공유 DB 정상 시 기존 요청 직렬화·캐시·서버 기록.
2. 공유 DB 첫 연결 실패(`read-cache`, 연결/타임아웃) 시 **운영자가 명시적으로 켠** `MOMENTUM_RANK_DB_OUTAGE_FALLBACK_ENABLED=true`의 제한적 단독 관측 경로 활용.
3. 예외 경로는 warm worker 인스턴스 기준 시간당 최대 2회, 동일 범위 5분 간격, IP당 1시간 간격. 기존 외부 controller의 10분당 신규 3회 제한·중복 요청 합치기·30분 결과 재사용도 유지. 이는 **분산된 전역 보장이 아닌 단일 인스턴스 제한**이므로 대규모 공개 서비스용이 아니다.
4. 네이버 403·429 시 즉시 중단·24시간 워커 메모리 차단. 다른 경로를 순차 시도해 제한을 회피하지 않음. 캡차 해결/로그인 우회/무단 대량 측정 금지.
5. 실제 관측 결과에서만 순위 표시. 관측 가능 범위에서 찾지 못하면 순위 미확인. 추정 위치와 확정 위치 구분.
6. 공유 DB에 기록하지 못했을 때 이용자의 **해당 브라우저 localStorage + CSV 내보내기**로 기록 유지. 기기 간 동기화 불가. 기존 클라이언트 기록은 삭제하거나 변경하지 않음.
7. 공유 캐시 쓰기 오류가 발생해도 **측정 완료된 관측값을 폐기하지 않음**. 제공자 차단 결과 역시 숨기지 않는다.
8. 서버 요청은 GET/POST의 기존 경로를 유지. 공유 저장소 오류 상태는 안전한 진단 코드만 노출하며 토큰, 원문 SQL 오류, DB 주소는 노출하지 않음.

## 다시 정상 운영하기 위한 장기 조치
- Supabase 프로젝트가 실제 존재·활성 상태인지 해당 관리자 계정에서 확인한다. 현재 연결된 Supabase 플러그인에는 프로젝트가 나오지 않음. 반드시 기존 프로젝트를 정확히 확인하고 재연결해야 한다.
- Vercel의 서버 전용 `MOMENTUM_RANK_DB_URL`, `MOMENTUM_RANK_DB_SERVICE_KEY`를 올바른 활성 Supabase 프로젝트의 URL/secret로 복구한다. **GitHub 파일이나 채팅으로 비밀키를 공유하지 않는다.**
- `db/rank-live-cache.sql`의 테이블 2개와 `momentum_rank_claim`, `momentum_rank_block` RPC가 존재하고 서비스 역할에서만 허용되는지 검증한다. 기존 사용중인 DB라면 신규 마이그레이션을 무턱대고 실행하지 않는다.
- 읽기·공유요청 claim·쓰기·429 회로차단을 각각 시험한 뒤 비상 플래그를 `false`로 내리고 프로덕션 재배포한다.
- 별도 DB 없이 장기 운영하거나 공개 이용자가 많으면 영속적인 전역 요청 제한과 운영 한도, 허용된 측정 데이터 소스를 도입한다. 지금 비상 경로는 소규모 점검용이다.
- 참고: 최신 Vercel 배포가 READY이고 순위 회귀 테스트 작업은 PASS이나 기타 홈페이지의 오래된 통합 테스트와 브라우저 설치 작업은 실패 중으로, 전체 CI가 초록색이라고 주장하지 않는다.
