# 모멘텀마케팅 전업종 전환형 홈페이지 마스터 — 개발·영업 기준 v2

## 목적과 출시 상태
- **표준화 대상:** 검색 의도 → 문제·가치 제안 → 해결책 → 신뢰 근거 → 상품/가격/이용 정보 → FAQ → 실제 문의·예약·구매 완료 측정.
- **업종마다 달라야 할 것:** 첫 화면 레이아웃, 증거 형태, 콘텐츠 우선순위, CTA 동선, 핵심 정보, 시각 언어.
- **산출물:** `/portfolio/conversion/` 허브 + 독립 HTML/CSS 18종 `restaurant/`, `beauty/`, `b2b/`, `shop/`, `stay/`, `interior/`, `academy/`, `pet/`, `legal/`, `clinic/`, `auto/`, `fitness/`, `estate/`, `hrd/`.
- **구형 시안 종료:** `/website-samples/` 하위 구형 15개 웹 페이지는 제거하고 과거 URL에 영구 이동을 설정. 메인·포트폴리오·관리자 시안 목록은 신규 8종으로 전환. 회원·DB·인증·CRM 및 블로그/상세페이지 기능은 유지.
- 포트폴리오는 **가상 브랜드 시안**이며 납품 실적/매출/검색 순위 보장이 아님. 각각의 실전 문의·예약/결제 동작은 고객사 본 정보·서비스 연동 후 구현한다.
- **가격문구 확정:** “지금 보는 홈페이지 30만원으로 제작 가능합니다.” 작은 글씨 “호스팅비는 별도”. 실제 납품 범위/추가 기능/수정/세금 등은 개별 계약 및 표시광고 검토.
- 코드 작성 ≠ Vercel 운영 배포. 변경 PR 검사 통과 및 운영 실측을 구분한다.

## 1. 랜딩페이지 UX 공통 퍼널
1. Hero: `[업종/대상]+[핵심 가치]+[행동]` CTA 1 + 보조 1, 모바일 CTA 접근.
2. Pain point: **실제로 검증된** 기존 어려움(가격 찾기, 예약 혼동, 기업 문의 주저 등).
3. Solution: 확인 가능한 제공 기능 3가지로 정리.
4. Trust: 고객 승인 사례/프로세스/자격/작업 과정. 가짜 수치·후기·별점 금지.
5. Choice: 메뉴·서비스 유형·구매 정보·프로젝트 절차에 맞춘 정보.
6. FAQ: 비용, 추가금, 일정, 교환/환불, 상담 전 준비, 정확한 동작 설명.
7. Final CTA: 견적·예약·구매 중 실제 연결 대상을 명확히, 실패하면 완료로 표시하지 않는다.

## 3. 재사용 가능한 3종 카피
- 공감형: `[고객의 실제 불편] 없이 [원하는 상태]를 경험하세요.`
- 근거형: `[확인 가능한 기술·과정·지표]로 [고객의 목표]에 맞는 [서비스]를 설계합니다.`
- 직관형: `[지역/대상]을 위한 [핵심 서비스] · [즉시 이해할 수 있는 이점]`.
- 특징 3줄: `대상에 맞춤`, `편의/절차를 단순화`, `검증 가능한 근거/운영지원`.
- CTA: `내 상황에 맞는 견적 받기` / `서비스와 가격 확인하기` / `예약 가능한 날짜 확인하기`. 버튼의 실제 연결 기능과 일치해야 한다.

## 4. SEO 체크
- 클러스터: `업종·서비스×지역×문제·목적×구매 단계`, 페이지별 독립 콘텐츠가 있을 때만 URL 추가.
- title/description/OG/url/canonical/head H1·H2·H3 구조 명확히. JSON-LD는 보이는 실제 정보와 일치.
- 가상 브랜드 시안은 `noindex,follow`; 검색 가능한 실제 서비스 페이지와는 구분한다.
- CTA의 목적을 설명하는 링크 텍스트와 내부 링크, 이미지의 실제 내용을 설명하는 alt, 헤더 이미지 크기/우선 로딩 및 아래 이미지 지연 로딩.
- 운영 고객 사이트의 정확한 URL/상호/사진/위치/가격/예약/영업시간 입력 전 배포 금지.
- HTTPS, 200/404, site map, robots, Search Console/네이버 서치어드바이저 연결은 실제 도메인 배포 시 확인.
- Google Core Web Vitals 권장 양호 기준 LCP≤2.5초, INP≤200ms, CLS≤0.1; Lighthouse와 실제 사용자 데이터를 구분.
- **공식 Google 가이드:** https://developers.google.com/search/docs/fundamentals/seo-starter-guide
- **네이버 서치어드바이저:** https://searchadvisor.naver.com/guide

## 5. 프론트엔드 운영 기준
- 사이트는 서버에서 전달하는 정적 HTML에 본문·헤딩·링크가 들어 있으므로 JS가 차단되어도 본문은 읽을 수 있다.
- 14개 홈페이지는 각각 독립 HTML에 독자 CSS를 포함하여 공통 프레임 의존을 제거. 허브의 비교 전시는 목적상 공통 스타일을 사용하지만 개별 시안 내부 레이아웃을 통일하지 않는다.
- 업종별 별도 아트디렉션과 섹션 순서, CSS 반응형 기준 390/768/1440px 테스트, 키보드 탭과 FAQ 열림 테스트. 숙박 날짜·시공 견적 준비·교육과정 탭·반려견 상담 준비 기능은 고객 정보를 전송하지 않는 시연이며 실제 예약이나 견적 계산이 아님.
- Unsplash 시연 사진 URL은 실제 업로드 이미지/사용권 확보된 최적화 이미지로 교체. 사진 로드 실패 시 가독성이 유지되어야 한다.
- 고객 개인정보를 받는 실제 문의는 기존 모멘텀 문의 폼과 CRM을 재사용한다. 가상 브랜드 시안의 가짜 폼/가짜 구매 CTA를 만들지 않는다.

## 6. B2B 영업용 케이스 스터디
**[실제 고객명 또는 '가상 디자인 시안']**

- 상황: `[업종/지역/고객의 선택 과정]`.
- 제작 전 실제 문제: `[정확한 근거가 있는 콘텐츠 문제/전환 병목/검색 이슈]`.
- 해결 방향: `고객 검색의도 분석→섹션 우선순위 변경→카피와 근거 작성→SEO/모바일 반응형→문의 연동`.
- 사용자 행동: `[방문/예약/문의/상품 선택]`을 고객 여정에 맞게 연결.
- 실제 제작후 관측: 검색 노출/클릭, CTA 클릭, 유효 문의/예약, 광고 출처, 요청 당 비용. 데이터가 없으면 **측정 예정**.
- 업종불문 3대 성공 조건: ①검색 의도에 바로 답하기 ②사실로 신뢰 구축 ③완료 이벤트까지 측정하기.
- 문의 CVR=`유효 문의 수/랜딩 세션 수×100`; CTR=`CTA 클릭 세션/CTA 노출 세션×100`.
- 목표 개선 수치는 가정으로 명시하며 계약상의 성과 보장은 하지 않는다.

1. 기존 사이트·회원/관리자·DB 회귀 테스트.

3. 브라우저 1440/390 폭 넘침/콘텐츠 노출/FAQ·CTA 경로, 실패시 원인 수정.

5. Vercel Production READY·commit SHA·도메인 별칭 실제 일치, 운영 사이트 경로 재검증.
6. 서치콘솔 색인 상태·실제 GA4/CRM 완료 이벤트 테스트. **연결하지 않은 항목은 미완료로 표시**.
